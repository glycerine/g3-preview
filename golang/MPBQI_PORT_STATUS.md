## Concrete representation and owner hierarchy

```go
type BinaryInterval struct { lower, upper BinaryRational }
func NewBinaryInterval() BinaryInterval
func NewBinaryIntervalManager(bounds *BinaryRationalManager) (*BinaryIntervalManager,error)
```

The default scalar has two source zero endpoints; for open configuration it is empty according to source representation equality. There is no ownership ID in each hot record; its numerical owner is implicit as in committed BinaryRational. Never shallow-copy owning intervals; Copy is two source Set operations, Swap is two source endpoint swaps. The manager borrows one live BinaryRationalManager, which in turn borrows its IntegerManager/diagnostic service. Caller intervals and scoped owners must die before the interval manager closes; close that manager before its borrowed bounds manager and underlying owners.

The interval-manager cold header contains the borrowed pointer, self/closed guard and source `mulCurr`, `mulMax`, `mulMin` BinaryRational fields. The source constructor performs no numeral arithmetic or eager payload allocation. Reserve exactly the actual concrete header through bounds.z.budget; its three scalar scratch endpoints are charged once inside that header, and big payloads are ordinary owner-local cells/Words under the existing budget. No phantom per-endpoint heap-node charge, additional numerical owner, copied borrowed owner-header charge, or unaccounted four-product array. Destructor order is Del mulCurr, Del mulMax, Del mulMin, then release the Go header; it closes no borrowed owner. Stats report own header and live scratch numerator roots, with numerical owner stats remaining distinct.

ScopedBinaryInterval is a concrete cold lexical owner with manager pointer, scalar BinaryInterval, self/closed guard, actual header charge and no per-endpoint Go pointer. New creates default scalar endpoints only; Close source-Dels lower then upper and refunds its own header. Repeated Close is idempotent; shallow copied owners, nil/copied/closed managers and mismatched scoped owner provenance receive existing typed guard errors. Manager operations remain owner-confined; a borrowed diagnostic mutex does not make interval arithmetic or a shared Budget concurrent.

Raw endpoint pointers from Get/Lower/Upper are borrows, not ownership transfers; they remain valid only within the live owner operation and may not be shallow-copied as owning numerals or retained past reset/swap/close. Do not provide an implicit scoped copy constructor/Assign/Clone: unlike scoped_numeral, this source scoped_interval declares no deep-copy constructor, and its implicit C++ copy would shallow-copy owning bounds. Explicit manager Copy is the legitimate value copy route. Existing `CopyFrom` may be used at a future owner boundary, but this packet will not accept foreign raw cell handles as same-owner Int/BQ inputs.

Inv and Div are **not executable MPBQI specializations**: the generic source requires `numeral_manager::field()` plus m.inv/m.div, while mpbq_manager declares field=false and has neither member. Instantiating those generic functions for MPBQ cannot compile. Do not invent public interval Inv/Div, implement them with ApproxDiv, or claim an unsupported diagnostic is a field inverse algorithm. They remain explicitly uninstantiable here, pending a different field-backed interval specialization.

## Exact source algorithms, quirks and prefixes

- Source open-set predicates: Empty is BQ structural Eq(lower,upper), Pos is NonNeg(lower), Neg is NonPos(upper), ContainsZero is Neg(lower) && Pos(upper). There is no hidden lower<upper validation, infinity support, empty flag or mixed openness. `(0,0)` therefore reports Empty, Pos and Neg true, ContainsZero false. Mathematically equal raw endpoint representations can report nonempty. Singleton setters are allowed even though the source comment says their manager must be closed: the body has no such guard and MPBQI explicitly exposes the Int singleton setter.
- SetBounds checks source Le(lower,upper) in g3debug, then publishes lower Copy and upper Copy. SetLower/SetUpper likewise check only their source ordering assertion before publishing that endpoint. Go provenance and initialization guards precede arithmetic, but do not invent a global interval-order check: legitimate source error prefixes or raw endpoint borrows can leave unordered bounds that still need Del/Reset/query access. Release source ordered-precondition behavior versus g3debug typed invariant failures stays explicit.
- IsSubset is Le(b.lower,a.lower) && Le(a.upper,b.upper). Precedes is Le(a.upper,b.lower), and scalar overloads use the corresponding upper/lower comparison. Preserve short-circuit evaluation so a false first comparison does not allocate scratch through the second.
- **Open Disjoint source defect:** `Le(a.upper,b.upper) || Le(b.upper,a.lower)` (first term compares upper to upper, not upper to b.lower). Thus `(0,3)` / `(1,4)` reports true despite overlap; the reverse reports false; a nonempty interval can report disjoint from itself. Freeze these finite source results separately from mathematical interval oracles. Do not silently correct the comparator or call conventional geometric separation.
- Add and derived AddInteger publish lower before upper. Sub is `a.lower-b.upper` then `a.upper-b.lower`; preserve output aliases and resulting rereads. With a=(2,4), b=(1,3), out=b, source publishes (-1,5), while a separate output is (-1,3). With a=b=out=(1,3), source yields (-2,5), not mathematical (-2,2). No new prohibition on source aliases and no whole-interval rollback.
- Mul computes all four source corners in this order: lower*lower, lower*upper, upper*lower, upper*upper. After the first product, Copy current to min then Swap max/current. Each update compares current<min and conditionally Copies min; independently compares current>max and conditionally Swaps max/current. Finally Swap out.lower/min, then out.upper/max. Retained scratch now owns the old output endpoints; this is actual ownership, not a leak to wipe by generic Reset. Do not replace by four local exact products, generic min/max, sign-pattern shortcut, or rational multiplication. Inputs may alias output because products precede publication.
- Power calls bound Power lower then upper before sign tests. Odd n finishes immediately. Even n rereads **a.lower** and **a.upper after those writes**, then returns unchanged for NonNeg(a.lower), swaps for Neg(a.upper), otherwise swaps if output lower>upper and Resets output lower to zero. Output=input aliases must retain this source defect: (-3,-1)^2 in-place produces (9,1), while separate output produces (1,9); (-2,3)^2 in-place produces (4,9), while separate output produces (0,9). For separate output and n=0 with nonzero straddling endpoints, source even branch produces (0,1), not (1,1). Keep inherited 0^0, exponent-product, PowerDomain and budget errors with their completed Copy/exponent/endpoint publication prefixes. Source n%2 assertion in its even branch remains build-aware, not an independent arithmetic substitute.
- Neg negates lower then upper before swapping. If the upper operation fails, the completed lower mutation survives. Set/Copy/Power preserve completed lower publication when upper fails; Mul retains partial scratch/old outputs according to source ordering. Existing BQ/MPZ primitive staging remains inherited; no new whole-pair atomic transaction. All Go error paths still clean their actual lexical owned roots immediately.

## Formatting and numerical callback boundaries

The source interval manager has **no external callback registry**: template substitution resolves every m() action to the borrowed numerical manager. Concrete Go methods call the approved BinaryRationalManager directly. No generic numeral interface, per-record boxing, reentrant callbacks, manager ownership transfer or user hook is needed to implement MPBQI.

Formatting uses the existing bounds.z.natural owner workspace and exact numerical decimal conversion. Append `(`, the lower endpoint text at its current offset, `, `, upper endpoint text, `)`. Calling existing BinaryRational.String/prepareBinary at offset0 while composing would overwrite the prefix or allocate intermediate strings; instead the new formatter composes the same existing prepareInteger, appendUnsigned and static punctuation helpers at explicit offsets. No changes to committed formatting helpers are necessary. Text workspace growth keeps the entire prefix; source numeral arithmetic/printing order is retained. FormatInto stages all text and leaves caller bytes unchanged for short buffers/budget failures; one final escaped Go string is caller-owned. Persistent ostream failbit/format-state integration remains separate, exactly as in the committed numeric display packet.

Actual downstream callback evidence: polynomial.h::var2value defines virtual `m()`, `contains(var)`, and `operator()(var)->const Value&`, with var2mpbqi specialization; polynomial::manager::eval accepts this mapping. algebraic_numbers.cpp::var2interval returns its owner bqim, includes only non-basic mapped values, and returns the algebraic cell's stored interval by reference. Its add_interval_proc/mul_interval_proc functors call bqim.Add/Sub/Mul, and interval refinement updates those same cell intervals. These mappings borrow the algebraic owner/var2anum table and must never transfer an owning shallow copy or survive owner deletion/refinement invalidation. Future Go callback specialization needs concrete operation-scoped owner/slot/generation validated interval borrows; its storage must remain with the algebraic/polynomial owner, not a fake MPBQI callback cache. Implementing that mapping, lookup tables, resource/cancellation policy, algebraic cell roots, and polynomial evaluation is outside this manager packet. The manager/scoped Get APIs preserve the necessary lexical borrow contract without claiming those consumers implemented.

The realclosure.cpp local typedef also named mpbqi_manager is `math/interval/interval_manager<mpbq_config>`; it has infinity/openness/approximate-division policy and is a different source unit. Do not merge it into this API or claim its callbacks/flags ported.
