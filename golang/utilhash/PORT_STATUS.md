Representation decisions: all source unsigned arithmetic is fixed-width uint32 (uint64 in hash_ull); overflow wraps. Source string_hash uses machine-endian memcpy loads and implementation-defined char signedness. The fixture baseline is little-endian and signed-char (this source on Linux/amd64); the Go port fixes those semantics on all targets including wasm. This is a recorded adaptation, not a replacement hash. `WordBytes` feeds the same hash state transitions using an allocation-free word/byte accessor for the bit-vector hash. Inputs must fit source uint32 lengths. `Bounded(0)` and zero-child Composite are invalid preconditions and panic in Go; they do not invent a valid result. Random state belongs to its caller, with no global RNG or math/rand substitution.

Unported source scope: identity hash functors (`int_hash`, `unsigned_hash`, `size_t_hash`, `uint64_hash`, `bool_hash`), object/handle/pointer adapters, `triple`, and pair/triple functor wrappers. Pointer-address hashing needs the coordinator's compact handle convention and cannot use unsafe/raw addresses. `triple_hash`'s declared pair parameter accesses `.third`, an existing dormant template issue to inventory rather than silently fix. The later concrete u_map<unsigned> packet is described below; other hash-table/map specializations and util.h functions remain separate unported components. This status does not declare the whole util component complete.

## Concrete u_map<unsigned> packet

Added `uint_map.go` and `uint_map_test.go`, translating the **u_map<unsigned>** instantiation of `src/util/map.h` and its `core_hashtable<default_map_entry<...>>` substrate in `src/util/hashtable.h`. Copyright Microsoft 2006, Leonardo de Moura. This is distinct from `src/util/uint_map.h`'s direct-index unsigned→T* vector and from the local UintSet-key `uint_map<unsigned>` defined inside `src/test/uint_set.cpp`. Those two variants remain separate unported components. No nonexistent src/test/uint_map.cpp or hash_params source was assumed. Identity `u_hash`/`u_eq` is implemented as key/key-equality, not hash_u, combine_hash or weighted UintSet hashing.

Algorithm fidelity: keys/values/hash/state/counters are uint32. The hot array contains exactly four scalar uint32 fields per entry (16 bytes), with no per-entry pointers, interfaces, generics or unsafe. Zero and UINT32_MAX keys/values remain legal. Lookup and mutation probe linearly from key&(capacity−1) and wrap once. Insertion remembers the **last** deleted slot encountered and uses it only on reaching a FREE slot; existing-key Insert overwrites only its value, while insert-if-absent retains it. Expansion runs before lookup when (size+deleted)*4 > capacity*3, so an existing-key update/duplicate can expand. Cached hashes are preserved across ascending-bucket rehash. Remove uses FREE only if the next wrapped bucket is FREE; otherwise it makes a tombstone and attempts same-capacity cleanup only when deleted>size AND deleted>64. An out-of-memory callback suppresses that cleanup, matching the source branch.

Reset counts buckets already FREE before clearing, **not** tombstones. It halves once only if capacity>16 and free*4>capacity*3; an already empty clean reset returns immediately. Finalize allocates 64 buckets when current capacity>64, otherwise follows Reset. Clone rehashes at source capacity and removes tombstones; Assign calls destination Reset then source bucket-order Insert rather than copying storage. Union overwrites shared-key values in source bucket order; intersection retains destination values for shared keys and removes keys absent from the source through a temporary clone. All thresholds, equal-boundary cases, source growth-before-duplicate behavior, wrapped probes, tombstone selection and resulting bucket order have exact finite tests.

Budget/ownership adaptations: UintMap imports only the independent arena Budget/error contract. Construction charges its cold owner header, then the 8-entry array; failed construction rolls back charges. Reallocation reserves the full new array while the old array remains charged, so peak old+new memory is bounded before mutation/publication. Close releases both charges. Failed expansion/Clone leave the source intact. Source Remove logically deletes before cleanup; a cleanup allocation error therefore returns an error with that removal completed and a still-valid tombstoned table, covered explicitly. Reset/Finalize allocate before releasing/clearing old storage; their failures are intentionally atomic instead of reproducing source post-delete allocation failure corruption. Cross-budget Swap reserves incoming ownership charges before releasing outgoing charges and rolls back failed transfer; its source-independent resource callback/header stay with each owner. Primitive values need no logical retain/free; future domain wrappers storing handles must perform their source logical reference actions outside this utility.

Cold `UintMapEntryRef` and iterator wrappers contain owner/table epoch/bucket, never a raw backing-array pointer. Structural membership mutation/reset/swap/reallocation invalidates these checked nonowning snapshots; value overwrite updates the existing bucket without invalidation. This is explicitly stricter than raw C++ pointer borrow lifetimes. Source mutable value references are represented by `SetValue`; callers cannot silently mutate a key while retaining its old cached hash. Missing required-key lookup and invalid/closed snapshots fail explicitly. Scalar table backing and epochs are owner-local; concurrent use requires owner synchronization. Array lengths/byte charges are checked in uint64 against platform int bounds. Capacity growth beyond the source's safe uint32 load-predicate range (2^30 buckets) is diagnosed before overflow/allocation; byte arithmetic does not wrap. Epoch rollover is diagnosed instead of validating an old snapshot.
