## Evidence and current boundaries

Authoritative bodies read: `src/util/mpz.h/.cpp`, `src/util/mpq.h/.cpp`, current `mpnum/mpz.go`, `mpz_slab.go`, arithmetic/division/number-theory/bitwise/power/shift/root/parser/inspection files, rational arithmetic/mixed-operation/root/rounding/parser/number-theory/inspection files, and `mp_copy.go`. Source allocation topology was checked against `small_object_allocator.h/.cpp`. Source tests were searched in `src/test/mpz.cpp` and `src/test/mpq.cpp`; direct source assertions are not interchangeable with independent arithmetic properties or injected-failure expectations.

The completed core now frees undersized temporary cells before replacement allocation; publishes transferred result cells before replacement scratch allocation; preserves sequential paired quotient/remainder output publication; publishes big-copy sign before destination free/allocation; preserves direct Div/Mod caller-output actions and divisor alias rereads. Missing scratch is guarded at its actual subsequent use. One charged, permanently retired failed allocation token per owner represents otherwise dangling replacement state. It is not a live numeral, a C++ cell or a source malloc event. Cleanup may clear that exact owner token; ordinary reads still reject it. These are explicit Go ownership continuations, not source exception recovery.

The current `normalizeOwned` in `mpz_power_shift.go:83` implements `mpz.cpp:1597` normalization: scan leading zero limbs, Reset on all-zero, Del then signed inline publication when the sole limb fits INT_MAX, otherwise adjust size. Older prose saying standalone normalization is unimplemented is stale. This helper is already called by shift algorithms. It is not a missing arithmetic algorithm.

## Actual allocator topology and global accounting dependency

C++ MPZ cells are one small-object allocation (`sizeof(mpz_cell)+4*capacity` for this limb profile), not a separate descriptor allocation plus limb allocation. Source `small_object_allocator` selects aligned slots below `256-(1<<PTR_ALIGNMENT)`, maintains free lists, and allocates 8192-byte chunks (data excludes two pointers). Release allocation increments requested m_alloc_size before chunk/raw allocation; small free refunds logical requested size and retains free-list/chunk backing. Z3DEBUG non-Windows bypasses these lists and calls memory::allocate/deallocate directly. Large objects use raw allocation; chunk exhaustion uses strict `<` bound. Host pointer width affects threshold, rounding and cell header size. This must be a selected platform contract, not guessed from Go reflect sizes.

Current numericCellSlab + Words charges actual Go metadata/payload/page/directory old/new peaks with Budget and a retired failure descriptor; NaturalManager owns actual scratch/text storage. This is honest Go accounting but NOT source malloc topology, physical reuse profile, m_alloc_size or global memory::get_allocation_size. Existing `util_memory_runtime` is root-package private and not composed into IntegerManager. It cannot be claimed automatically integrated via Budget. The mpnum package cannot import parent g3 (cycle); a coordinated concrete storage/accounting owner boundary is a prerequisite, not permission to invent function callbacks or label Budget.Used source TLS counters.

The next logical publication packet can preserve current Go physical owners with explicit peak adaptations. True source allocator/global topology needs a separate reviewed layout: exact profile, real small-block/free-list/chunk owner, real SIZE_T-prefixed raw memory routes and TLS/nonTLS failure ordering, and lifetime/refund integration. No phantom source headers or synthetic malloc events for slab records. Raw MPZ locals have no destructor; deferred Go cleanup and constructor unwind are explicitly safer exception-lifetime adapters. No recovery claim after dangling C++ pointer or lost scratch.
